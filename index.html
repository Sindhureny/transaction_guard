Phase 1: Ingestion

TRANSACTIONS Table

Raw ledger records containing TRANSACTION_ID, ACCOUNT_ID, AMOUNT, TRANSACTION_TIME, and MERCHANT. Uses primary key constraints and idempotent DDL.

Phase 2: In-Memory Windowing

Analytic Window Functions

Leverages Exasol's columnar in-memory calculation engine. Window partitions evaluate duplicate billing and daily transaction velocity simultaneously without costly table self-joins or slow procedural loops.

Phase 3: Composite Scoring

Risk Scoring & Concatenation

Rule weights sum to a holistic score (0-100). Concatenates all active heuristic flags into plain-language audit trails, preventing secondary triggers from being masked by single CASE statements.
